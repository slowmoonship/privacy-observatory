# 数据更新和故障处理

`python3 scripts/update_data.py` 独立处理 market（PriFi 历史市值及 XMR 供应）、activity（Coin Metrics）、pools（ZecStats）。网络请求 30 秒超时，429、5xx 和连接错误最多三次，间隔 1、2 秒；失败组保留已有快照，成功组分别验证后原子替换。每组来源、许可、非负有限数值、必需字段、日期及新鲜度均需通过；最新观测超过 4 天、未来时间、空序列、日期重复、两币交易覆盖首尾不一致均拒绝。断档显示 null，不插值。

脚本在 `data-status.json`（默认被 gitignore；可用 DATA_STATUS_PATH 改位置）记录每组成功/失败、是否变化、错误和 `checked_at`，以及总体状态和 `publishable`。退出码 0 为三组成功且快照可用，2 为部分成功且三份快照均仍可用，1 为全部失败或缺少、损坏、过期的快照。部分成功可使用保留的旧快照继续构建；没有可用核心快照或全部失败时禁止持久化和构建发布 artifact。状态文件作为本次运行 artifact 留存，不提交到仓库，避免每次时间戳变动产生提交。

比较业务数据时忽略 `generated_at` 与 `fetched_at`，只在数据、观测日期、覆盖或口径等变化时替换文件。`python3 scripts/check_data.py` 可独立复核三组快照。Actions 先运行测试、采集与质量检查，再构建，最后仅提交 `public/data/{market,activity,pools}.json` 中真正变化的文件；它们须以非商业用途使用。提交不由 push 触发此工作流，因此不会递归，上传的 Pages artifact 来自同一运行。并发串行化，推送冲突会使运行失败而不会强推。

刷新时间为每天 04:37 UTC（北京时间 12:37），也可手动触发。定时任务实际启动可能延迟。部分失败时状态 artifact 和日志保留失败原因；页面仍以原始观测时间显示，并在超过三天时提示可能过期。4 天是本地质量门槛，不是来源对更新频率的保证。
